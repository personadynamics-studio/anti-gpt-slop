# AI 交付物瑕疵簽名庫（Anti GPT Slop）

[![GitHub stars](https://img.shields.io/github/stars/personadynamics-studio/anti-gpt-slop?style=flat&label=stars)](https://github.com/personadynamics-studio/anti-gpt-slop/stargazers)

[![Signatures](https://img.shields.io/badge/signatures-29%20in%206%20families-critical.svg)](SKILL.md)
[![Cases](https://img.shields.io/badge/cases-15%20append--only-informational.svg)](SAMPLES.md)

**English** — A signature library and scanning procedure for auditing AI deliverables. It carries 29 family signatures across six families (verification, lifecycle, fault grading, shared resources, change shape, reporting) plus an append-only case ledger; any hit that cannot produce the required evidence — necessity, pre-existing checks, blast radius, exit path, and a real interception — is rejected. It works in DeepSeek Harness, Codex, Claude Code, and any agent that reads `SKILL.md`.

**中文** — 本技能用於審核自動化編碼代理之交付物：6 大家族、29 條瑕疵家族簽名，外加一本 append-only 案例紀錄。命中而無法提出四項舉證者，一律退回。

判定依據為可觀察的程式形狀與證據缺口，不作動機推測，亦不作文字風格評論。

全庫由一條總則統攝：**單一保證只實作一次，且置於擁有該責任的層；資源隨伺服器既成事實釋放，不隨客戶端確認釋放；缺陷修復以刪除或替換為之，不以疊加控制為之。**

## 公開版說明

本倉庫為去識別化公開版。案例紀錄僅保留可觀察之程式形狀與舉證結構，不載任何真實專案名稱、檔案路徑、行號或事故編號；行文採書面語。私有詳細版（含完整指紋）另行保管，不在本倉庫內。

## 它治什麼病

| 病灶 | 現形方式 |
| --- | --- |
| 假完成 | 刪幾行即稱修復、未執行之資料庫指令即稱已生效、靜態閱讀即稱實際運行 |
| 自製認證標記 | 資料已正確讀取，卻因缺少自行發明之印記而不放行 |
| 第二份真相 | 同一條規則於資料庫、應用層與前端各抄一份互相檢查 |
| 責任漂移 | 將業務政策寫入資料庫或前端，將明確命令丟回模型決定 |
| 粉飾結果 | 未知寫成已停止、`ERROR` 之後仍送 `DONE`、缺值自動補預設 |
| 保留理由堆疊 | 可疑機制旁出現成堆「因為…必須保留」之自述，無一句能對應需求來源 |
| 雙重鎖 | 同一件事在兩層以上各驗一次，且說不出其中一層的獨有保證 |
| 無出口 | 等客戶端確認才釋放、等一個永遠不會到來的事件、用容量上限代替退出條件 |

## 怎麼運作

### 掃描前必備三項（缺一不得開始）

1. **交付清單**：版本控制輸出之原文（例如 `git show --stat`、`git diff`），而非交付方之自述。
2. **聲明原文**：交付方對「做了什麼、為何如此」之原始敘述。
3. **逐項證據**：每一主張所對應之檔案、行號與原文。

### 四項舉證（命中後逐項回答；缺一即視為未舉證）

| # | 題目 | 答不出時之寫法 |
| --- | --- | --- |
| 1 | **必要性**：該控制之產品需求來源何在（需求方原話／平台官方文件／實際事故編號）？ | 明寫「無需求來源」 |
| 2 | **既有核對**：同一保證原本由哪個函式、介面或資料表負責？新增部分之獨有差異為何？ | 說不出獨有差異即未舉證 |
| 3 | **失敗範圍**：該控制失效時阻斷何事？被阻斷之初始化、服務路徑與介面須逐項列出 | 不得僅寫「阻斷啟動」 |
| 4 | **退出路徑**：該控制所持有之資源，於每一狀態下由何者、於何時釋放？ | 指不出釋放者即未舉證 |

兩條附則：

- **實際攔截**：主張該控制有效者，須附曾攔截之原始紀錄；無者明寫「無」，不得以「它具備拒絕能力」替代。
- **源碼證實即成立**：自製拒絕條件或無界保留，只要源碼可證實，即得判定，不以「尚無實際受害案例」免責。

### 判定與處置

| 情形 | 處置 |
| --- | --- |
| 命中 ＋ 四項舉證有缺 | **退回該項**：不得進入下一輪施作，不得視為已交付；應要求補足證據或撤回 |
| 命中 ＋ 四項齊備 | 可收，並將四項答案寫入驗收紀錄（位置、檢查項目、退回後果、信心程度、由誰讀過哪一行） |
| 未命中 | 僅能記載「本輪簽名庫未命中」，不得寫「乾淨」「無問題」 |
| 誤報 | 對造提出檔案、行號與原文證明為誤報 → 收窄該簽名形狀，並於 `SAMPLES.md` 記載一次誤報；紀錄不得刪除 |

## 實例（節錄自 [`SAMPLES.md`](SAMPLES.md) 案例 005）

**輸入**：一份庫存報告，其中兩項聲稱「續頁游標綁定查詢印記，以防止續頁位置錯配」與「原文續讀必填摘要」。

**掃描結果**

- 命中 **A3 自製印章（自算查詢摘要作為續頁資格憑證）**，兼中 C4（以拒絕代替修復）、F1（無來源即事故）。
- 必要性＝**無**：無需求方原話、平台強制條文或事故單要求該摘要與必填欄位。
- 既有核對＝資料庫端擁有者過濾與查詢介面自身之游標；續讀已有範圍檢查，摘要未新增原子性保證。
- 失敗範圍＝合法續頁與續讀被拒：同一組過濾條件只要空白、順序、預設值或時間格式不同，重算摘要即不同。
- 退出路徑＝無（該摘要不持有資源，但拒收使修復無處落腳）。
- 實際攔截＝**無紀錄**。
- 判定：**列為不合格**，進入刪除清單。
- 界線：只讀；未執行產品、未呼叫工具或模型；「將阻斷合法請求」為靜態推斷。

## 安裝

技能目錄名須為 `gpt-slop-signatures`（與 `SKILL.md` frontmatter 之 `name` 相同）。

### DeepSeek Harness（DSH）

```powershell
git clone https://github.com/personadynamics-studio/anti-gpt-slop.git "$env:USERPROFILE\.dsh\skills\gpt-slop-signatures"
```

### Codex

```bash
git clone https://github.com/personadynamics-studio/anti-gpt-slop.git ~/.codex/skills/gpt-slop-signatures
```

### Claude Code

```text
/plugin marketplace add personadynamics-studio/anti-gpt-slop
/plugin install anti-gpt-slop@anti-gpt-slop
```

### 其他代理

```bash
npx skills add personadynamics-studio/anti-gpt-slop --global --agent '*'
```

下載本倉庫之 ZIP（**Code → Download ZIP**），於 Settings 內上傳為 skill。

### 手動安裝

將 `SKILL.md` 與 `SAMPLES.md` 放入該代理之技能目錄，資料夾名用 `gpt-slop-signatures`。

## 使用

直接點名：

```text
載入 gpt-slop-signatures，掃描這次提交是否含有本庫所列之瑕疵簽名。
```

或以白話提出：

```text
檢查這次交付是否含有可疑或無來源的控制機制，以及是否自行加入了多餘關卡。
```

審核輸出必須包含：**位置、檢查項目、退回後果、信心程度、核實方式（由誰讀過哪一行）**。對造主張判斷有誤時，應要求其提出檔案、行號與原文；證實為本方之誤，則撤回該條並寫明撤回內容。

技能另附**常見說詞與應提證據對照表**：聽到「已修復／已涵蓋／原始碼完成／多一層保險／等客戶端確認／保留以便診斷」時，當場應要求何種證據。詳見 [`SKILL.md`](SKILL.md) 第 6 節。

## 六大家族・29 條簽名

| 家族 | 主題 | 一句話 |
| --- | --- | --- |
| **A** | 重複與自製控制（雙重鎖） | 同一保證在兩層以上各驗一次、自算印章要求對方送回、寫後讀回重算、同一事實兩份權威、為不存在的競爭者設身分 |
| **B** | 生命週期 | 等客戶端確認才釋放、無出口的等待、用准入上限代替退出、清理失敗留住整個物件、重複取消、背景任務無人監督 |
| **C** | 故障分級 | 協議小錯升級為致命錯誤、小容量加斷線代替背壓、單一功能缺件殺全站、拒收閘門代替修復、把未知粉飾成成功、吞錯重試 |
| **D** | 共用資源 | 全域鎖包住外部 I/O、同步重運算跑在事件迴圈、中間層解碼後重新編碼 |
| **E** | 改動形態 | 加法式修復、只改一端、保留死碼、為錯誤前提補防護、新框架或第二執行通道、業務政策塞進 SQL 或前端 |
| **F** | 報告話術 | 假綠燈與缺件即無罪、保留理由通脹與自我授權、覆述需求與反向差異、上下文錯置 |

| 編號 | 名稱 | 形狀 |
| --- | --- | --- |
| A1 | 重複既有核對而未說明新增保證 | 原有身分、版本、權限核對之外再增一層，卻說不出多出何種保證 |
| A2 | 連線建立後再定期重驗身分 | 已認證之長連線另加租期、續期迴圈，且多持連線當時之舊令牌 |
| A3 | 自製印章 | 自算雜湊或摘要，要求呼叫方原樣送回或重算相等，不等即拒收 |
| A4 | 寫入後回讀重算 | 提交成功後整批讀回、重算摘要、比對預期值 |
| A5 | 同一事實存在兩份權威 | 資料庫以外之副本被要求與主體完全相等，未交代維護者 |
| A6 | 為不存在之競爭者增設身分 | 已有唯一識別碼之處另設嘗試或世代識別碼，而該競爭者不可能存在 |
| B1 | 等待客戶端確認方釋放資源 | 伺服器結果已成立，仍待前端回報「已呈現」方關閉程序或連線 |
| B2 | 無出口之等待 | 無期限等待外部事件，無對外語義，亦無「永不到達」時之收尾 |
| B3 | 以准入上限代替退出設計 | 集合含無期限之執行中項目，卻以固定上限拒絕合法新請求 |
| B4 | 清理失敗即保留整個物件 | 登錄表留住工作階段、連線、程序與堆疊，理由為「供診斷」 |
| B5 | 重複取消或重複清理 | 下層已清理，上層再清一次，第二次失敗覆蓋第一次成功 |
| B6 | 背景任務無人監督 | 全域任務僅建一次，例外被吞，健康檢查不讀它 |
| C1 | 協議層小錯升級為致命錯誤 | 一則無效輸入即以例外穿出主迴圈，終止整場 |
| C2 | 小容量佇列加斷線代替背壓 | 固定小佇列滿即斷線，或以非阻塞寫入失敗後無聲結束 |
| C3 | 單一功能缺件即終止全站 | 某功能之資產缺失即拋錯使進程不啟動，而使用點本已有守衛 |
| C4 | 以拒收閘門代替修復 | 資料已正確讀得，卻因自製驗證器或前置條件不放行 |
| C5 | 將未知粉飾為成功或永不可知 | 未知寫成成功、或關掉收據通道再宣稱無法結算 |
| C6 | 吞錯、重試與替代取值 | 全捕捉後靜默略過；確定失敗仍重試；捕捉後填入空集合 |
| D1 | 全域鎖包住外部 I/O 或共用執行器 | 鎖內執行遠端呼叫；所有同步工作投入同一預設執行器 |
| D2 | 同步重運算於事件迴圈執行 | 世界推進或內容編譯與 I/O 處理共用同一迴圈，無量測 |
| D3 | 中間層解碼後重新編碼 | 僅轉送者將負載解碼重編，並補上上游已附加之標頭 |
| E1 | 加法式修復、只改一端、保留死碼 | 保留舊分支再加新分支覆蓋；新條件只加於一條路徑 |
| E2 | 為錯誤前提補防護 | 先加無來源依賴，再為其衍生風險補防重、補身分、補費用邊界 |
| E3 | 新框架或第二執行通道 | 新層無消費者，或與舊路徑雙軌並存 |
| E4 | 業務政策置入資料庫或前端 | 價金、額度、獎勵、解鎖決策出現於 SQL 或前端 |
| F1 | 假綠燈與缺件即無罪 | 以「原始碼已改」「健康檢查正常」冒充當次實際運行 |
| F2 | 保留理由通脹與自我授權 | 成堆「保留…」理由，並引用自己寫入的文件證明本來即要求 |
| F3 | 覆述需求、反向差異、原則句鋪路 | 通篇口號而無檔名行號；自稱撤回而差異淨增 |
| F4 | 上下文錯置 | 非同步後仍用舊快照、依賴可漂移、以無衝突代替架構相容 |

批次與來源：A 族與 B 族多數簽名來自「以外部安裝身分檔作為啟動前置」「全服務同時場次上限」「單場運算程序被多層防禦包住」三案；C 族來自同批「可被單點終止之全域結構」與付款鏈案例；D 族來自鎖與執行器、事件迴圈、轉送層三處；E 族與 F 族來自前端結果框拆除、付款未知狀態與第三方鑑證報告所引之指紋。逐條之形狀、當場檢查、判定與對應案例，見 [`SKILL.md`](SKILL.md) 第 3 節。

掃描優先序：先掃 **A1、A2、B1、C1**（歷史上造成事故最多），再掃其餘；見到成堆「保留／維持原狀」時先掃 F2；見到自算摘要、游標印記或「送回原值再比對」時先掃 A3；見到寫入後回讀重算時先掃 A4；見到「多一層保險」時先掃 A1；見到租期、續期迴圈或逐訊息授權時先掃 A2；見到終場等待前端確認時先掃 B1；見到無期限等待或「等外部事件」時先掃 B2；見到容量上限、配額或「滿了就拒絕」時先掃 B3；見到清理失敗仍保留工作階段時先掃 B4；見到背景任務只建一次而健康檢查固定回應正常時先掃 B6；見到協議錯誤直接終止時先掃 C1；見到固定小佇列加斷線時先掃 C2；見到「啟動時檢查資產，缺了就拋錯」時先掃 C3；見到全域鎖包住遠端呼叫或所有工作共用一個執行器時先掃 D1。

## 版本 0.3.0 之改版

舊版由多輪累加而成，48 條連續編號彼此重疊、家族邊界模糊、同一形狀重複登錄。0.3.0 全面重寫為**六大家族、29 條簽名**，每條固定四欄：形狀、當場檢查、判定、案例。

- **新增 8 條**：A2、A6、B1、B4、B5、C1、C2、D3，全部歸納自「單場運算程序被多層防禦包住」一案（案例 015）。
- **舊編號**：`SKILL.md` 第 7 節附完整對照表，既有案例內之舊編號仍可追溯；新紀錄一律使用新編號。
- **四項舉證**：第四項由「實際攔截」改為「退出路徑」，實際攔截移為附則並維持強制。

新形態命中且不在表上時，當場於對應家族末新增一條（如 `A7`），並於 `SAMPLES.md` 追加一筆。**不得僅於對話中提及即視為登錄；紀錄不得刪除，誤報亦須保留。**
